# Реферальная программа на дни подписки — дизайн

**Дата:** 2026-07-12
**Ветка:** `feature/bot-redesign-onboarding`
**Статус:** утверждён к реализации

## Проблема

Текущая реферальная механика (`app/services/referral_service.py`) построена на деньгах:
комиссия % с пополнений, бонус рублями за первое пополнение, разовый бонус
пригласившему, вывод реф-баланса. У FreekVPN бизнес-модель — бесплатный VPN с
триалом 14 дней; денежные начисления в реальности почти не срабатывают, поэтому
экран рефералки помечен заглушкой «⚠️ ВРЕМЕННО НЕ РАБОТАЕТ»
(`REFERRAL_TEMPORARILY_DISABLED_NOTICE`).

## Цель

Заменить денежную механику на начисление **дней подписки**:

- **Реферер:** +3 дня за каждого приглашённого.
- **Реферал:** +7 дней.
- **Условие:** реферал оформил **покупку подписки ≥ 100 ₽** (реальная покупка, не пополнение баланса).
- **Разово** за каждого реферала (при его первой квалифицирующей покупке).
- Если у получателя нет активной подписки — реактивировать/создать от текущего момента.
- Денежную механику (комиссия %, бонусы рублями, вывод) — полностью отключить.

## Решения по дизайну

| Вопрос | Решение |
|--------|---------|
| Триггер | Реальная покупка подписки ≥ 100 ₽ (не пополнение баланса) |
| Повторность | Разово за каждого реферала (первая квалифицирующая покупка) |
| Получатель без активной подписки | Реактивировать/создать от текущего момента |
| Старая денежная механика | Полностью заменить на дни |
| Куда вешать хук | Сервисный слой на завершении платной покупки (Вариант 1) |

## Секция 1 — Конфиг и данные

### Новые настройки (`app/config.py` + `.env.example`)

| Настройка | Дефолт | Смысл |
|-----------|--------|-------|
| `REFERRAL_REWARD_REFERRER_DAYS` | `3` | Дней рефереру за квалифицированного друга |
| `REFERRAL_REWARD_REFERRED_DAYS` | `7` | Дней рефералу |
| `REFERRAL_PURCHASE_THRESHOLD_KOPEKS` | `10000` | Порог покупки (100 ₽) |

### Отключение денег без удаления кода

Меняем дефолты на `0`:

- `REFERRAL_COMMISSION_PERCENT = 0`
- `REFERRAL_FIRST_TOPUP_BONUS_KOPEKS = 0`
- `REFERRAL_INVITER_BONUS_KOPEKS = 0`
- `REFERRAL_WITHDRAWAL_ENABLED` — уже `false`.

Существующий код везде гейтит на `> 0`, поэтому нули глушат денежную логику чисто,
ничего не переписывая и не удаляя. Механика остаётся дремать — обратимо.

### Аудит

Новый `reason='referral_days_reward'` в `ReferralEarning` (`amount_kopeks=0`).
Число начисленных дней рефереру для статистики вычисляем как
`count(referral_days_reward rows) × REFERRAL_REWARD_REFERRER_DAYS`. Без миграции БД.

Поля `ReferralEarning`: `user_id` (реферер), `referral_id` (реферал),
`amount_kopeks`, `reason`, `created_at`.

## Секция 2 — Механика начисления

Новая функция в `app/services/referral_service.py`:

```
process_referral_subscription_reward(db, buyer, amount_kopeks, bot)
```

**Точка вызова:** завершение платной покупки подписки — общий сервис покупки
(`app/services/subscription_purchase_service.py`) плюс хендлеры покупки, чтобы
покрыть оба пути (бот и веб-кабинет). Точные точки уточняются на этапе плана.

**Логика:**

1. У `buyer` нет `referred_by_id` → выход. Само-реферал (`buyer.id == referrer.id`) → выход.
2. `REFERRAL_PROGRAM_ENABLED=false` → выход.
3. `amount_kopeks < REFERRAL_PURCHASE_THRESHOLD_KOPEKS` → выход.
4. **One-time гейт:** если уже есть `ReferralEarning(reason='referral_days_reward')`
   для пары (реферер, buyer) → выход. Защита от дублей тем же SELECT-guard-паттерном,
   что в `process_referral_registration`.
5. Начисляем дни через `extend_subscription` (`app/database/crud/subscription.py:867`):
   - **buyer** (реферал): `extend_subscription(sub, +REFERRED_DAYS)` — подписка только что куплена, активна → +7 в конец.
   - **referrer:** `sub = get_subscription_by_user_id(...)`.
     - Есть строка (даже истёкшая) → `extend_subscription(sub, +REFERRER_DAYS)`
       (активная → +3 в конец; истёкшая → +3 от «сейчас»).
     - Строки подписки нет вовсе → создаём минимальную подписку на `REFERRER_DAYS`
       дней от текущего момента (хелпер уточняется в плане: `create_*_subscription`).
6. Пишем маркер `ReferralEarning(reason='referral_days_reward', amount_kopeks=0)`
   и шлём обоим уведомления.

**Изоляция ошибок:** весь блок начисления обёрнут в `try/except` — сбой начисления
(в т.ч. синка Remnawave) логируется и НЕ откатывает покупку buyer.

### Поведение `extend_subscription` (существующее, не меняем)

- Подписка активна: `end_date = end_date + timedelta(days=N)` (дни добавляются в конец срока).
- Подписка истекла / отсутствует: `end_date = now + timedelta(days=N)` (реактивация от текущего момента).

## Секция 3 — Экран рефералки и уведомления

### Экран (`show_referral_info`, `app/handlers/referral.py`)

- Убираем баннер `REFERRAL_TEMPORARILY_DISABLED_NOTICE`.
- Расширяем `get_user_referral_summary` (`app/utils/user_utils.py`): добавляем
  `qualified_count` = число строк `referral_days_reward` у реферера. Дни =
  `qualified_count × REFERRAL_REWARD_REFERRER_DAYS`.

Текст (все строки — через `texts.t(...)`, RU-дефолты):

```
👥 Приглашай друзей — получай дни VPN 🎁

За каждого друга, который оформит подписку от 100 ₽:
• ты получишь +3 дня
• друг получит +7 дней

Приглашено: {invited}
Оформили подписку: {qualified}
Тебе начислено: {days} дн.

Твоя ссылка:
<code>{link}</code>
```

Кнопки без изменений: `📋 Скопировать` (`CopyTextButton`),
`📤 Поделиться` (`t.me/share/url`), `← Назад`.

### Уведомления (переписываем с денег на дни)

**При регистрации по ссылке** (`process_referral_registration`):

- Другу: «Ты пришёл по ссылке друга. Оформи подписку от 100 ₽ — получишь **+7 дней** в подарок.»
- Рефереру: «Твой друг зарегистрировался. Когда он оформит подписку от 100 ₽ — тебе **+3 дня**.»

**При начислении** (новая функция):

- Рефереру: «🎁 Твой друг {name} оформил подписку! Тебе начислено **+3 дня**. Действует до {date}.»
- Другу: «🎁 Спасибо за покупку! Как приглашённому — тебе начислено **+7 дней**. Действует до {date}.»

Все тексты — через `texts.t(...)` с RU-дефолтами (единый i18n-подход проекта).
Значения дней/порога в текстах подставляются из настроек, не хардкодятся числом.

## Секция 4 — Крайние случаи и тесты

### Крайние случаи (все — «пропустить награду, покупку не ронять»)

- Само-реферал / реферер не найден / у buyer нет реферера → skip.
- `REFERRAL_PROGRAM_ENABLED=false` → механика дней отключена целиком.
- Сумма < порога → награды нет, покупка проходит.
- Повторная квалифицирующая покупка того же реферала → маркер-строка блокирует дубль.
  Гонки — тот же SELECT-guard, что в регистрации.
- Продление/renew — тоже платная покупка ≥ 100 ₽, но маркер не даст начислить
  повторно (соответствует «разово за реферала»).
- Активация триала — не покупка → триггера нет.
- Ошибка начисления (сбой `extend_subscription` / синка Remnawave) — в `try/except`,
  логируется, покупку buyer не откатывает.
- Покупка из веб-кабинета и из бота — хук в общем сервисе покупки покрывает оба пути.

### Тесты (pytest, по TDD — сначала тест, потом код)

- Порог: ниже / на границе / выше.
- One-time гейт: повторная покупка не даёт второго начисления.
- Само-реферал → без начисления.
- Отключённая программа → без начисления.
- Реферер с активной подпиской → +3 в конец `end_date`.
- Реферер с истёкшей / без подписки → +3 от «сейчас».
- Buyer → +7 к его подписке.
- Изоляция ошибки: сбой начисления не ломает покупку.
