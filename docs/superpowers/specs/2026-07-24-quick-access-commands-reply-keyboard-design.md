# Быстрый доступ: меню команд `/` + нижняя reply-клавиатура

Дата: 2026-07-24
Ветка: `feature/bot-redesign-onboarding`

## Цель

Добавить в бота FreekVPN два «быстрых» способа навигации в стиле Lagom VPN,
не трогая существующее inline-меню:

1. **Меню команд** (список по кнопке «/» слева от поля ввода) — регистрируется
   через `bot.set_my_commands(...)`.
2. **Постоянная нижняя reply-клавиатура** (2 колонки) — «ставится» отдельным
   коротким сообщением на `/start` и висит в чате постоянно.

Оба механизма — тонкие обёртки над уже существующими экранами. Никакой
дубль-логики: каждая команда/кнопка открывает ровно тот же экран, что и
соответствующая inline-кнопка.

## Немодифицируемое

- Существующее inline-меню (`get_main_menu_keyboard`, карточка-статус) остаётся
  как есть. Reply-клавиатура и команды — дополнительный слой навигации.
- Механика покупки, гайда, рефералов, инфо, поддержки, промокода не меняется —
  переиспользуем.

## Меню команд `/`

Регистрируется в `setup_bot()` (`app/bot.py`, перед `return bot, dp`) через
`bot.set_my_commands([...])`. Порядок и подписи:

| # | Команда | Подпись | Открывает экран |
|---|---------|---------|-----------------|
| 1 | `/start` | Главное меню | главное меню (существующий `/start`) |
| 2 | `/connect` | Как подключиться? | `install_guide` (без активной подписки → «Оплатить») |
| 3 | `/pay` | Оплатить | `menu_buy` |
| 4 | `/referrals` | Рефералы | `menu_referrals` |
| 5 | `/promo` | Ввести промокод | промо-флоу (ввод кода) |
| 6 | `/info` | Инфо | `menu_info` |

Подписи команд — через locale-ключи (см. ниже), язык `ru`. Область видимости —
дефолтная (все приватные чаты); отдельный scope для админов не вводим.

## Нижняя reply-клавиатура

Раскладка (2 колонки, `resize_keyboard=True`, `is_persistent=True`):

```
[ Как подключиться?           ] [ Ввести промокод              ]
[ Политика конфиденциальности ] [ Пользовательское соглашение  ]
[            Поддержка (во всю ширину)                          ]
```

Роутинг по тексту нажатой кнопки:

- **Как подключиться?** → тот же экран, что `install_guide`
  (`show_install_guide_devices`). Если у пользователя нет активной подписки →
  открываем экран «Оплатить» (`menu_buy` → `start_subscription_purchase`).
- **Ввести промокод** → промо-флоу: присылаем запрос кода и ставим FSM-состояние
  `PromoCodeStates.waiting_for_code` (как `show_promocode_menu`). Ввод кода ловит
  существующий `process_promocode`.
- **Политика конфиденциальности** → сообщение с inline URL-кнопкой на
  `PRIVACY_POLICY_URL` (telegra.ph). Если ссылка не задана → фолбэк на
  in-bot просмотр (`menu_privacy_policy`).
- **Пользовательское соглашение** → сообщение с inline URL-кнопкой на
  `USER_AGREEMENT_URL`. Фолбэк → `menu_public_offer`.
- **Поддержка** → экран/сообщение поддержки: кнопка на `@FreekVPN_SupportBot`
  (`SUPPORT_USERNAME`) + «Создать обращение» (`support_request`), если тикеты
  включены. Переиспользуем существующий `show_support_info`.

## Как «ставим» клавиатуру

Одно сообщение не может нести одновременно inline-разметку (карточка меню на
фото) и reply-клавиатуру — это разные `reply_markup`. Поэтому:

- На `/start` бот **перед** карточкой главного меню отправляет одно короткое
  текстовое сообщение (напр. приветствие/подсказку) с `reply_markup =
  <reply-клавиатура>`. Telegram запоминает клавиатуру в чате.
- Дальше все обычные inline-экраны работают как раньше; reply-клава остаётся
  внизу постоянно.
- Клаву шлём на каждый `/start` (идемпотентно с точки зрения UX — Telegram просто
  обновляет её). Флаг «показана однажды» не вводим (YAGNI).

## Архитектура

Новый модуль `app/handlers/quick_access.py`:

- `get_quick_reply_keyboard(language) -> ReplyKeyboardMarkup` — строит клавиатуру
  из locale-ключей. (Альтернатива — добавить в существующий `app/keyboards/reply.py`;
  выбор — в плане реализации.)
- `register_handlers(dp)` — регистрирует:
  - `Command(...)`-хендлеры на 6 команд;
  - `Message(F.text == <текст кнопки>)`-хендлеры на 5 reply-кнопок, с
    `StateFilter(None)`, чтобы не перехватывать ввод в тикетах/промокоде/др. FSM.
- Тонкие адаптеры `_open_*`, которые открывают целевой экран **новым сообщением**
  (`message.answer(...)`), а не редактированием.

### Переиспользование существующих экранов

Целевые рендеры сейчас привязаны к `CallbackQuery` (делают `edit_text`). Для входа
из `Message` их нельзя вызвать напрямую. Стратегия по каждому экрану:

- **Главное меню** — уже есть message-путь в `/start`; переиспользуем его билдер
  (`get_main_menu_text` + `get_main_menu_keyboard`).
- **Инфо / Поддержка** — есть чистые билдеры (`build_help_contacts_screen`,
  экран поддержки); адаптер собирает caption+клавиатуру и шлёт новым сообщением.
- **Оплатить / Гайд / Рефералы** — где рендер жёстко завязан на `CallbackQuery`,
  выделяем минимальное общее ядро `render_*(message_or_bot, user, ...)`, которое
  вызывают и старый callback-хендлер, и новый адаптер. Точные рефакторинги —
  в плане реализации. Дубль рендера не создаём.
- **Промокод** — адаптер повторяет тело `show_promocode_menu` для message-входа
  (отправка `PROMOCODE_ENTER` + установка FSM-состояния).

Регистрация нового модуля — в `app/bot.py` рядом с прочими `register_handlers(dp)`.

## Locale-ключи (дефолты в `app/localization/locales/ru.json`)

Команды:
- `CMD_START`, `CMD_CONNECT`, `CMD_PAY`, `CMD_REFERRALS`, `CMD_PROMO`, `CMD_INFO`.

Reply-кнопки (тексты должны совпадать с матчингом в хендлерах — берём из одного
источника, не хардкодим дважды):
- `RK_CONNECT` = «Как подключиться?»
- `RK_PROMO` = «Ввести промокод»
- `RK_PRIVACY` = «Политика конфиденциальности»
- `RK_AGREEMENT` = «Пользовательское соглашение»
- `RK_SUPPORT` = «Поддержка»

Плюс короткое сообщение-«установщик» клавиатуры: `RK_INSTALL_HINT` (напр.
«Меню всегда под рукой 👇»).

Тексты можно переопределить на проде через `../ru-locales-live.json` (scp), но
дефолты в коде должны быть финальными (владелец предпочитает править тексты в
коде + rebuild, см. уроки в памяти).

## Крайние случаи

- **FSM-конфликт:** reply-кнопки шлют текст. Без `StateFilter(None)` нажатие
  «Поддержка» во время ввода тикета сломало бы флоу → все reply-хендлеры строго
  `StateFilter(None)`. Промо-флоу сам ставит состояние, поэтому reply-кнопки в
  нём не сработают — это ожидаемо.
- **«Как подключиться?» без подписки** → «Оплатить» (решено).
- **Пустые URL** политики/соглашения → фолбэк на in-bot просмотр.
- **Тикеты выключены** → «Поддержка» показывает только `@FreekVPN_SupportBot`
  без «Создать обращение» (как сейчас в инфо-экране).
- **Мультиязычность:** язык один (`ru`, `LANGUAGE_SELECTION_ENABLED=false`) —
  строим клаву/команды под `ru`, без «Switch to English».
